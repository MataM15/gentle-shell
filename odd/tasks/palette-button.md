# Palette button: clickable command palette entry points

Add mouse entry points to the Gentle Shell command palette (today Alt+K / `/gentle:commands`) in fullscreen mode.
Branch `feat/palette-button`, worktree `/home/pablo/proyectos/gentle-shell-worktrees/palette-button`. Approved mockups: `/mnt/c/Users/pablo/Pictures/pagub-review/palette-icon/v3/` (A3.png, C3.png, contact-sheet-v3.png).

## Specs

- **S1 (A3, rail card actions).** User: "me quedo con A3". In the right rail "✿ Gentle Shell" header card, replace the current `usage · alt+u` row with a dim dotted rule followed by two aligned action rows, as in mockup A3:
  - `☰ commands   [alt+k]`
  - `◔ usage      [alt+u]`
  Labels use the theme accent role, key hints and the rule use the dim role; the icon column and the key column align across both rows. User's complaint about the old row (verbatim): "eso de usage queda horrible".
- **S2 (A3 clicks).** A left click on the `commands` row opens the command palette exactly like Alt+K / `/gentle:commands`. A left click on the `usage` row opens the usage view exactly like Alt+U / `/gentle:usage` (current behavior preserved).
- **S3 (A3 key hints).** Key hints show the actually resolved shortcut (`GENTLE_PI_COMMANDS_KEY`, `GENTLE_PI_SHELL_USAGE_KEY` remaps); when a shortcut is disabled the row shows no key hint. When `visibility.usageCost === false` the usage row is omitted (existing opt-out preserved) and the commands row remains.
- **S4 (C3, editor border label).** User: "A3 siempre visible y C3 solo cuando no está el panel lateral" (agreed: "ok dale"). On the input editor top border, next to the `✿` petal, render `✿ ☰ commands · alt+k` (resolved key; no key hint when disabled) ONLY when the right rail is not visible (`sidebarState(tui)` active && ownsHost false/absent, e.g. terminal < 140 columns or non-fullscreen). When the rail is visible the editor border is unchanged. Spacing: one cell between petal, icon, and label so they do not look cramped (user: "no queda muy alineado ... siento que no queda estetico"). Float card style gets the equivalent treatment in its hint row.
- **S5 (C3 click safety).** User concern (verbatim): "no se si cuando quiera hacer clic en el cuadro de dialogo y accidentalmente cliclee mal pueda abrir ese panel..". Only the `☰ commands` label cells on the border row are clickable; only a clean `click` event (press and release on the same cell, no drag) opens the palette; clicks on the input text rows and drags keep native editor behavior.
- **S6 (no regressions).** Existing behavior preserved: Alt+K, Alt+U, `/gentle:commands`, `/gentle:usage`, rail breakpoint transitions, stale-geometry guards, editor petal/state/scroll labels, foreign-editor ownership refusal.

- **S7 (glyph).** User approved the recommendation ("ok vamos con tu recomendacion"): use `≡` (U+2261, one cell) instead of `☰` everywhere (rail rows, editor label, palette hints), so icon and key columns align in real terminals; no double-space padding before `usage`.
- **S8 (narrow header bar).** At widths without the rail, the top header bar replaces the old `usage · alt+u` segment with the same action treatment (commands + usage, resolved keys, clickable), per approved mockup (T4).
- **S9 (no redundant info).** User (verbatim): "hay info redundante.. fijate de simplificar la info, yo dejaria en todo caso la de estatus como cannon antes que se muestren en la de arriba". When the Status card is visible (rail), the "Gentle Shell" header card drops the project path/branch and profile lines that Status already shows; it keeps model · effort, ctx/cost and the action rows. Without the rail (no Status card), the top bar keeps them.
- **S10 (card titles).** User (verbatim): "fijate si lo podes mejorar todo.. no me convence mucho como se muestra [✿ Status, ✿ Limits, ✿ Bienestar titles] el de [✿ Gentle Shell] no me molesta, pero con los otros no se si es el color.. la flor o que.. a y tambien [❀ Todos ▼ Collapse · 2 of 3 title]". Restyle the bordered card titles (Status, Limits, Bienestar, Todos) per user-picked variant **T-b** (`/mnt/c/Users/pablo/Pictures/pagub-review/palette-icon/v4/R-Tb.png`): no flower on the border title, title text in the accent/rose role (bold), one space each side; Todos keeps `▼ Collapse · 2 of 3` dim and right-aligned on the border. Narrow bar (S8) uses mockup N row 1 (`≡ commands alt+k · ◔ usage alt+u`) and falls back to row 2 (`≡ alt+k · ◔ alt+u`) when labels do not fit.

- **S11 (palette mouse).** User (verbatim): "aca no puedo hacer clic en \"esc\"" (screenshot of the open command palette). In fullscreen, a clean left click on the header `esc` or the footer `esc close` closes the palette like Esc; a click on a command row runs that command like Enter; group titles, blank rows, the search row and the card border are inert; the wheel moves the selection like ↑/↓; presses, drags and clicks against a stale geometry (different width/height than the last render) do nothing. The footer hint names the click: `enter/click run` (fits the 60-column minimum).

- **S12 (palette icons).** User (verbatim): "Si.. y podrias implementar iconos para que sea mas visual?". Add icons to the command palette per the variant the user picks from mockups (T7). Every glyph must measure one cell in pi-tui `visibleWidth` AND render in one cell in a real terminal (tmux / Windows Terminal); no emoji, no Nerd Font, no East Asian Wide or Ambiguous glyphs.

- **S13 (sub-menu mouse).** User (verbatim): "y ojo que si sigo profundizando en la navegacion creo que deja de funcionar". Reproduced (L15): after clicking `Switch persona` in the palette, the follow-up Pi native `ctx.ui.select` list ignores a left click on `neutral`. Every sub-menu reachable from the palette must answer the mouse in fullscreen like the palette does: a clean left click on an option selects it like Enter, the wheel moves the highlight, clicks on the title/hint rows are inert, drags never select; keyboard behavior, results, cancel (Esc/ctrl+c) and regular-mode behavior stay exactly as today.

- **S14 (collapsible rail).** User (verbatim): "ok dale. pero antes una cosa mas .. podemos hacer que [right rail screenshot] se pueda ocultar? como [herdr left sidebar screenshot] que tiene la opcion abajo..". The right rail gets a clickable collapse control at its bottom (like herdr's `«`), and a way to reopen it while collapsed; plus a keyboard shortcut and a palette entry. Collapsed, the transcript and editor use the full width and the editor border shows the C3 commands label (the rail's actions are gone). Exact look per the user-picked mockup (T10).
